Entry points
  Add-machine dialog button:   Pair device…
Title
  Pair device
Headings
  1. Show this PC's code
  2. Enter a code
Buttons
  Generate code
  Review
  Accept pairing
  Close
  Copy commands            (only when elevation is needed)
Field labels / placeholders
  target placeholder:      this PC as the peer reaches it: user@100.x.y.z
  code placeholder:        wooloo-pair-v1:...
  checkbox:                Add an Include line to ~/.ssh/config so plain ssh also knows this peer
Copy-box / result text
  After Generate code:     Send this code to the other device (and compare fingerprints there):
                           [readonly code box], then "key <fp>", "host <fp>", "Herdr: <path or not found>"
  After Review:            <label> (id <id>) at <target>, session <s>, herdr <v>; key / host / Herdr lines;
                           "Accepting lets that device's key run only Herdr bridge commands on this PC
                           (entry in <authorized_keys path>). Check the fingerprints match what the other device shows."
  After Accept (ok):       Paired with <label>.
  After Accept (needs elevation):
                           Paired, but this PC's <path> still needs the peer's key (<reason or "needs an elevated write">).
                           The line to add:   [readonly box]
                           Or paste this into PowerShell run as Administrator:   [readonly box]
Errors: shown in red from the backend; "Pairing needs the desktop app." in a browser.

Local server errors (red dot reason)
  Pipe access denied (os error 5):  The Herdr server was started by a different (elevated) user context. Stop it with: herdr server stop (in the window where you started it) and click Start Herdr
  Rule: never start herdr from an Administrator window; the server's pipe then denies the normal app.

Test connection (machine row, lightning icon, title "Test connection"; SSH machines only)
  Runs read-only, stops at the first failing hop. Lines: "ok|skip|FAIL  <label> - <detail>", then the hint. "Close" hides the result.
  Labels: Tailscale ping; TCP port 22; SSH login; Herdr bridge; Reverse: peer to this device, TCP 22
  Reverse (shown after a TCP/SSH failure, informational): tells you to run on the peer: Mac `nc -vz <this device's Tailscale IP> 22`, Windows `Test-NetConnection <ip> -Port 22`.
  TCP 22 timeout hint: if Shields Up is off, suspect a Tailscale ACL / grant not allowing tcp:22 between the two devices, or a relay-only path ("via DERP"); then the other device's firewall and Remote Login / sshd.
  Other hints: refused -> turn on SSH server; ssh auth -> pair again (Windows: elevated commands); bridge -> start Herdr on the other device.
